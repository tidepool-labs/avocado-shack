## R1. Execution order, fields and exits

`Jobs.pump` dispatches a **plan** when no version has been frozen and a **render** when there is one, keyed by `(segment_id, revision, n)`. It does not execute an S1–S13 array. The S-labels below identify responsibilities, not the sort order: picture selection (S6) happens before the main copy call (S5), and capture (S8) happens before the final S7 verdict. Copy's own field checks occur earlier during S5. S1 and S12 label the intake and apply boundaries in this crosswalk. See `hass/npp/job.py:368–436`, `hass/npp/stages.py:172–229`, `hass/npp/copy.py:227–292`, `hass/npp/assets/README.md:7–17`, and `hass/tests/test_npp_undo_journey.py:1–5`.

In the next table `npp/` means `hass/npp/`. “Writes” includes in-memory outputs; it does not imply a database, catalog or transport write. Plan, Card and Work fields are defined at `hass/npp/job.py:93–121`.

**Cross-cutting exits and evidence.** At the segment deadline, `ProductionStages.cap` uses local render if a listing exists, declines an unfinished parent edit with no listing, or tries a fresh local plan (optionally paired with its render); a late future is ignored even if complete. Worker/cap exceptions become `None` and take the ordinary failure path; request expiry closes the job and its open questions/segments (`hass/npp/stages.py:257–263`, `hass/npp/job.py:168–177,368–435`). `Jobs.answer` binds a duplicate/near-maker answer to the sole open question and eligible request; ordinary missing-info questions resolve as the plan changes (`hass/npp/job.py:232–253,323–348`).

`Jobs.write_receipts` is observational, not a stage or approval input: per job it exports `job_id,state,photo_sha,created_at,closed_at,polish_started_at`, segment `accepted_at,ended_at,outcome`, version `n,listing_sha,image_variant,image_sha256,change_id,draft_hash,card_png_sha,outbox_id,delivered_at,state`, and `asset_pins`. `receipt.Artifacts.write_receipt` replaces the JSON atomically; write failure is logged. That is separate from positive transport confirmation and from `evidence.Evidence` (a separate validated collector for stage/model/fallback/check/approval/publish evidence, not called in this production dispatcher). `hass/npp/job.py:458–480,525–539`, `hass/npp/receipt.py:28–41,92–105`, `hass/npp/evidence.py:101–169`.

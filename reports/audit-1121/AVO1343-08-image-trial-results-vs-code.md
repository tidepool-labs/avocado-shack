## R4. Gaps, in priority order

1. **Wrong fallback expectation for new listings.** The historical house result should not be used to infer a safe raw preview. The current NPP checks can turn that fallback into a retake, and the general flow doc still calls it silent house fallback (R2 variant/raw rows and docs; T5 `/2/decision`, `/5/decision`).
2. **New timing and picture-identity rules are not measured in the archive.** Stored timing and the T5 edit hash don't exercise the NPP wait boundary, restart, or byte identity across render/apply. Source and synthetic checks are separate evidence (R2 timing and freeze rows; `hass/tests/test_npp_photo.py:108–154`).
3. **Model and gate coverage is narrow.** Six inputs per tier and fixed gate settings do not qualify new tiers, prompt revisions, OCR outages or acceptance boundaries; the house-only harness is not a replay of HASS-IMAGE-1 (R1, R2). No model choice follows.

**One proposed follow-up, not implemented** (estimate: 60–90 minutes; separate file reservation required): in `docs/hass/NEW-ITEM-FLOW.md` only, distinguish the historical T5 result and ordinary installer behavior from NPP's raw/house/retake branches, and link to the S6 policy and this count audit. Offline acceptance: use the R1 recount below and read `hass/ops/photos.py:229–265`, `hass/npp/picture.py:66–110` and `hass/npp/stages.py:219–229`; require the doc to describe both the intake-on polish-failure raw candidate **and** the raw-check refusal, and to retain house fallback for the non-intake installer. A blanket “all failures publish house” or “all failures publish raw” fails that comparison. No runtime, wording-policy or model change needed.

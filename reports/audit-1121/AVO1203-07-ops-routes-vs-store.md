## R2. Publish boundary and quoted guards

**Publish class inside `hass/ops/`: none.** `Op.apply` is a callback; the editor calls it on a copy (`base, new = content_revision(wt), copy.deepcopy(content)`), not on a live checkout (`hass/ops/__init__.py:41–45`, `hass/editor.py:186–217`). The host's mode-bound editor sends only a live-bound draft to the live engine (`hass/host.py:441–449`, `hass/sandbox_editor.py:112–134`, quote: `if binding['env'] == 'live':`). The separate `hass.install.install` is a configured *local* site copy of an applied, unreverted, matching writer commit, not a Git push (`hass/install.py:112–137,147–177`; quote: `"the change is not applied"`).

| Outside `hass/ops/` | Approval or guard as written |
| --- | --- |
| `LiveEditor.apply` — normal typed release (`hass/publish_live.py:286–332`) | Checks environment when wired, release lock, STOP, readable and settled release records, unreleased change ID, matching draft hash (`'the draft no longer matches'`), current site state and writer/site baseline. Applies cap/spacing logic and `if reasons := live_policy.check(draft): return self.refuse('; '.join(reasons))`. For an undo it also checks `_landed_change` for every original. This is an apply gate, not the code that authenticates a chat yes. |
| `LiveEditor.pipeline` — build and stage a release (`hass/publish_live.py:338–383`) | Rechecks recorded environment for non-baselines; runs checked build and refuses `'unexplained-diff'`, `'privacy'` or `'empty-build'` before staging/committing to the site repo. Records `built` and `committed` before calling `push`. |
| `LiveEditor.push` — public site repo write (`hass/publish_live.py:400–424`) | `if self.stopped(): self.fail(j, 'stopped')` (two lines in source); journals `'pushing'` before `self.git('push', 'origin', j['site_commit'] + ':refs/heads/main')`. Uncertain outcomes become `'unknown'`, not proof of delivery; later reconciliation checks the served manifest (`hass/publish_live.py:434–490`, `hass/release_journal.py:164–177`). |
| `LiveEditor.revert_last` / `operate` — attended alternatives (`hass/publish_live.py:526–546,571–572,597–621,627–638`) | Revert selects a previously landed, not-already-undone change and uses the same `apply`; baseline requires exact build confirmation and privacy check (`if confirm != manifest or risks:` goes to preview); retry requires the existing `'not-published'` entry, no STOP, no already-landed commit, matching site state and recorded environment check when applicable. These are not new `OPS` routes. |

**Who supplies approval to the typed path.** Ordinary chat narrows approval to the owner's proposal (`self._mine(r)`), refuses late, premature or paused approvals, and requires a code where configured or required for that draft. A tracked legacy listing preview must match the hash and have a sent picture outbox row: `"I haven't sent the picture for this version yet. Please wait for the picture before confirming."` The chat records the approval with the change ID, hash and base before invoking `editor.apply` (`hass/conversation.py:1387–1475,1189–1215`). Chat undo makes a proposal there, not an immediate publish (`hass/conversation.py:2709–2739`). NPP requires the current delivered card and a yes sent after its delivery (`target["state"] != "delivered"` and `sent <= at` are refusal conditions); it then checks expiry and binds `change_id`, `draft_hash` and `base` to that exact version before recording approval (`hass/npp/job.py:479–516`, `hass/conversation.py:1605–1631`).

The checked-in stock writer is a separate source caller for `product.set_availability`: code returns `'off'` for off mode, selects approved sets or separately policy-qualified automatic batches, checks pause and writer/cap headroom, then calls `self.live.apply(d['change_id'], d['draft_hash'])`. This is source reachability, not evidence the automatic route is enabled or authorized now (`hass/stock_site.py:131–147,197–229`). The chat path for an approved combined till/site draft has its own readback and stale-base checks before site apply (`hass/conversation.py:1218–1255`).

**Which writes can pass.** The 18 `Yes*` rows in R1 are the keys of `LIVE` (`hass/live_policy.py:183–202`); even a listed row can fail on arguments (`"not live: {call['op']}.{arg}"`), protected fields/claims, record limit or sign-up (`"sign-up is on"`). `product.edit` is limited to ID/description/category; `maker.edit` to key/story; `product.add` takes a stored photo rather than an `image` path on this route, and `maker.add` must be with a new product (`"maker.add without a new product"`). `history.revert` as an undo-only draft skips the operation table but not the record/content checks or the prior live landing check. A `No` row is not inferred to be generally safe to publish just because it has a renderer or a private writer (`hass/live_policy.py:185–206,330–336,441–506`, `hass/publish_live.py:299–319`).

## R4. Ranked gaps

1. **Highest — registry and release eligibility are distinct.** A reader following registration alone cannot distinguish a private draft from a live-eligible draft or from the result actually served. `product.set_restock` is a concrete case: it writes a private field, has a producer, and the test for the live table expects `"not live: product.set_restock"` (`hass/ops/restock.py:20–50`, `hass/skills/restock.py:105–137`, `hass/tests/test_live_table.py:112–118`). Do not infer that the allowlist should expand.
2. **Next — “check” and “install” obscure side effects.** The photo check can fill a private web-copy cache, and the photo install stages bytes for the writer, distinct from the local site installer and the live publisher (`hass/media.py:391–418`, `hass/ops/photos.py:158–169,268–304`, `hass/install.py:112–137`, `hass/publish_live.py:400–424`).
3. **Lowest — `house_check` has test callers only in this scan.** That is a maintenance signal, not evidence the seam is dead or should be removed; the tests cover render and install byte parity (`hass/tests/test_house_render_seam.py:131–158,413–428`; R3).

**No build unit needed from this audit.** The observed gap is knowing which boundary a call crosses; this report supplies that map. The source does not establish a release defect that requires a behavior change. No code, test, data, page, workflow or policy change proposed.

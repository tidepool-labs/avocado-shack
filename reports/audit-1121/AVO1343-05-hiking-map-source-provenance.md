## R4. Ranked gaps and one optional follow-up

1. **Input-to-install link.** Neither install listing names or hashes the map inputs or metadata. The pinned commit lets a reader recover them from Git, and the October 27 receipt identifies the site outputs checked, but there is no per-file chain in the receipt (R1 listings and `/commit`; R3 replay).
2. **Exact source inventory.** Four exact filenames are missing from Sources; the USGS service snapshot lacks an explicit saved-file role and retrieval date. The retained records do not by themselves establish the upstream image acquisition dates or settle any licence or attribution question (R2; Sources lines 24–37 and 62–74). Those decisions stay with the owner.
3. **Repeatable bytes.** The subset is both fallback input and rewritten output; its node order differed in the offline replay. That matters for byte hashes even though parsed content and the site JSON matched (Builder lines 7–10 and 51–53; R3).

**One possible later unit (estimate: 75 minutes; not done here):** Add only `reports/hiking-club/point-buchon-provenance-manifest.json`, identifying the seven files by relative path, role, source-note anchor and Git blob ID; link the historical receipt commit/pointers to the checked outputs and explicitly mark absent evidence rather than implying the sources were installed. Offline acceptance: use `git ls-tree -r` and `git rev-parse <recorded-commit>:<path>` to verify the seven-row path and blob match; use `jq` to resolve the referenced receipt entries; in a scratch copy, substitute a wrong blob ID and require the comparison to report that row.
